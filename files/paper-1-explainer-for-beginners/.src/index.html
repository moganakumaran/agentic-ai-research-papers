Does a notebook help an AI get better at SQL?

We gave an AI a notebook of its past mistakes. Everyone assumed it would help. We tested it fairly, on 100 pairs of similar questions, with two different AI models. It did not help at all - and the reason why matters for your day job.

The job, in one picture

Think of the AI as a junior data analyst. You ask a question in plain English. It writes SQL, runs it on the database, and gives you an answer.

You ask“What were total sales in California last month?”
→
AI writes SQLSELECT SUM(amount) FROM sales WHERE ...
→
It runsQuery runs on the database
→
You get an answerA number, a table, a chart

If the SQL is wrong, the answer looks fine but is wrong. That is the dangerous part - especially when the query runs without an error and returns a plausible number.

The notebook idea everyone believed

Now give that junior analyst a notebook: every past mistake, and how it was fixed. Next time a similar question comes up, they check the notebook first.

Without a notebook

AI → writes SQL from scratch → answer. Same kinds of mistakes can happen again and again.

With a notebook

AI → reads old fixes first → writes SQL → answer. Sounds smarter. Sounds obvious.

The key question: Does “sounds obvious” mean it actually works? For data work, nobody had tested it properly. So we did.

Two rules made the test honest

1
Keep it fair - same budget for everyone.

If the notebook version gets more thinking time, more tries, or more compute, it might win only because it spent more. So both versions got the same budget - like giving two analysts the same 30 minutes for the same task.

2
Check the answer key itself.

A test is only as good as its answers. If the official answer is wrong, a correct AI gets marked wrong - and a wrong AI can get marked right.

A real example: the fastest lap

The question was simple: “What is the fastest lap time?”

Lap time as textLap time in millisecondsWhat it really means
“2:00.000” - the official answer120,000 msSlower
“1:07.411” - the AI’s answer67,411 msFaster - actually correct

The official key compared the text instead of the numbers, so it picked the wrong lap. Our AI answered correctly and was marked wrong for being right. This was not rare. An independent audit found errors in over half the checked answers in this benchmark. So we scored everything twice: once with the original key, and once with a corrected key.

The notebook did not help - at all

On the second model, the score was 58.25% with no memory and 58.25% with memory - exactly the same. The first model showed the same pattern: no real gain. The notebook also cost more to run, because the AI spent time reading it. More cost, zero gain.

The one “win” was an illusion

We also tried a different trick: write 3 queries and pick the best one. At first, it looked like a breakthrough.

With the original key: +9.8 points. With the corrected key: 0.0 points. The trick was not better at answering questions. It was better at matching the mistakes in the answer key. It also quietly used 17% more compute than it was allowed - like an analyst taking 35 minutes when everyone else got 30.

When the database quietly changed

In real pipelines, meaning drifts without warning. Example: a column called revenue used to store dollars. One day it silently starts storing cents. Same name, same table - answers are suddenly 100x off. That is drift.

Accuracy fell from 53.9% before the change to 30.8% after. Everyone got worse. The old notebook did not protect anyone - and, to be fair, it did not make things worse either.

Three things to remember

1. Check your answer key

Before you trust any score, check the test itself. A “better” tool might just be better at matching your test’s mistakes.

2. Compare at equal cost

Extra compute can disguise itself as extra intelligence. Always ask: did it win fairly, or did it just spend more?

3. Measure, do not assume

A notebook sounds like it must help. We measured it twice, on two models, fairly - and it did not.

Bottom line: This paper is not “AI memory is bad.” It is “here is how easily evaluations lie to you - and how to run one that does not.”

Based on Paper 1: “Failure Memory Does Not Help Data Agents: A Compute-Fair, Corrected-Label Evaluation.” Study: 100 pairs of similar questions, two AI models, scores reported on both original and corrected answer keys.
